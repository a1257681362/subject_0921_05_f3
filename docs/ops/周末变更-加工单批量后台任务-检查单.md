## 三、实施后验证（冒烟）

1. **提交即返回（不堵线程）**
   ```bash
   curl -s -u bootstrap:bootstrap -X POST http://localhost:8080/api/sensitive/recheck \
     -H 'X-Operator-Id:1001' -H 'X-Request-No:CHK-1' \
     -H 'Content-Type: application/json' -d '{}'
   ```
   - [ ] 立即返回 `data.taskNo`，初始 `status=PENDING`、`progressPct=0`。

2. **查进度（5% 档）**
   ```bash
   curl -s -u bootstrap:bootstrap http://localhost:8080/api/tasks/<任务号>
   ```
   - [ ] `progressPct` 始终是 5 的整数倍；跑完 `status=SUCCESS`、`progressPct=100`。
   - [ ] `resultJson` 含 `dictVersion / totalOrders / neverScannedOrders / driftCount / matchedFields`。

3. **看处理项（每单一行）**
   ```bash
   curl -s -u bootstrap:bootstrap "http://localhost:8080/api/tasks/<任务号>/items?limit=1000"
   ```
   - [ ] 每项 `itemStatus=SUCCESS`，`resultJson` 内含该单 `neverScanned / drifts / matchedFields`。
   - [ ] 历史直插（无写路径留痕）的单 `neverScanned=true`。

4. **取消**（可另起一个多单任务）：`POST /api/tasks/<任务号>/cancel`
   - [ ] 状态到 `CANCELLED`，已处理计数保留、`progressPct` 为 5 的倍数。

5. **断点重跑**：对被取消或 `FAILED` 的任务 `POST /api/tasks/<任务号>/rerun`
   - [ ] 只补跑未完成/失败项；最终 `SUCCESS`、全项成功；已成功项 `attempt` 不变。

6. **留痕不丢**：核对过程仍按单按字段写 `t_sensitive_scan_log`（`oper_type='RECHECK'`）。

## 附：任务接口速查（写接口均带三个审计请求头）

| 操作 | 方法与路径 |
| --- | --- |
| 提交反向核对任务 | `POST /api/sensitive/recheck`，body 可选 `{"storeCode":"S01"}` |
| 通用建任务 | `POST /api/tasks`，body `{"taskType":"SENSITIVE_RECHECK","params":{...}}` |
| 查进度 | `GET /api/tasks/{taskNo}` |
| 任务列表 | `GET /api/tasks?taskType=&status=&includeArchived=false` |
| 取消 | `POST /api/tasks/{taskNo}/cancel` |
| 断点重跑 | `POST /api/tasks/{taskNo}/rerun` |
| 处理项明细 | `GET /api/tasks/{taskNo}/items?status=&limit=200` |

任务状态：`PENDING → RUNNING → SUCCESS / FAILED`，可 `CANCEL_REQUESTED → CANCELLED`；终态超 21 天转 `ARCHIVED`。
